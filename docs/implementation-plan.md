# План реализации

1. Зафиксировать данные и критерии в BRIEF.md; согласовать JSON-контракты с исследователями и применить DESIGN.md дизайнера.
2. Написать и запустить падающие тесты нетривиальной логики: маршрутизация, нормализация ответов, выборка органов с предками, оценка квиза и проверка данных.
3. Реализовать `scripts/logic.js`, затем оболочку `index.html`, `styles.css`, `scripts/app.js`. Использовать только HTML/CSS/JS и стандартный Node test.
4. Интегрировать `data/structure.json`, `data/content.json`, эмблему из `assets/`. Не дополнять сведения без источников.
5. Добавить README, workflow `.github/workflows/pages.yml` и упаковщик, публикующий только файлы сайта.
6. Запустить полный набор тестов, проверку синтаксиса и сборки; передать root для независимой браузерной проверки.

## Файлы

- `index.html`, `styles.css`, `scripts/app.js`, `scripts/logic.js` — сайт.
- `data/`, `assets/`, `DESIGN.md` — контент/визуальные материалы других исполнителей.
- `tests/logic.test.js`, `package.json`, `scripts/build.mjs` — проверка и упаковка.
- `README.md`, `docs/implementation-report.md`, `docs/implementation.diff` — запуск, проверка и передача.

## Критерии готовности

- Все 5 страниц открываются прямыми hash-ссылками; ошибка маршрута возвращает структуру.
- Поиск учитывает название и должностных лиц, фильтры сочетаются, совпадения сохраняют цепочку родителей.
- Карточки показывают дату, официальный источник и отсутствие сведений без выдуманных ФИО.
- Квиз не оценивает незавершённые попытки; показывает правильные ответы, объяснения и перезапускается. Ответы загадок нормализуются.
- Видимый фокус, подписи полей, управление клавиатурой, мобильная навигация и состояния загрузки/ошибки.
- Сайт работает в подпути GitHub Pages, артефакт не содержит рабочие документы и тесты.
