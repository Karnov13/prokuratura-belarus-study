# Дизайн учебного сайта о прокуратуре Республики Беларусь

## 1. Назначение и границы

Статический учебный ресурс для чтения и исследования. Посетитель понимает устройство органов, находит проверенный материал и закрепляет знания. Это не официальный государственный портал и не канал отправки обращений. HTML/CSS/JS, GitHub Pages, без сервера, авторизации, сбора персональных данных и реального приёма документов.

Дизайнерское решение этой спецификации: тёмно-синяя компактная оболочка, светлая страница учебного издания, выразительные наборные заголовки, тонкие разделители и ясная иерархия. Никаких пустых hero, весов, молотков, случайных гербов, градиентов, карточек вокруг каждого абзаца. Основной режим Read; поиск и упражнения используют знакомые формы.

На момент спецификации присутствуют `data/structure.json` и `docs/structure-sources.md`, интерфейса нет. На этапе передачи исследователь расширил справочник до 149 органов и заполнил руководителей восьми верхних органов; статусы проверки определяются самим набором данных. Макеты показывают условные пустые состояния и композицию, а не актуальное покрытие или персональные сведения. Юридические факты, имена, перечни и условия службы заполняет исследователь; дизайн не подтверждает их истинность.

Это ссылки на разделы, не ARIA tabs: страницы/якоря должны открываться штатно, поддерживать Back, копирование адреса и новую вкладку. Шестой «Главной» нет. Зафиксированный контракт реализации: один `index.html`, hash-маршруты `#/structure`, `#/appeals`, `#/career`, `#/activities`, `#/interactive` соответственно порядку выше. Открытие без hash ведёт к Структуре, это не шестая страница. Back/Forward и прямой URL с hash восстанавливают нужный раздел. Для Pages все локальные href/src относительные, без корневого `/assets`; глубокие ссылки не требуют серверного rewrite. Якоря контентных блоков стабильные и латинские.

В начале документа: ссылка «К содержанию», далее header, nav с доступным названием «Разделы сайта», main с единственным H1, footer. Название сайта «Прокуратура Республики Беларусь» и подпись «Учебный сайт» в шапке. Название не выдаёт ресурс за официальный.

Пользователь выбрал файл 2026-11-08; это текущее основание использования, его внешнее происхождение не утверждается. Прямоугольный синий фон — часть изображения; сохранять весь файл, исходные пропорции и все детали, без обрезки, ретуши, генерации и растяжения. Контейнер desktop 128×67 px, mobile 96×50 px, object-fit: contain; рядом полное название Академии с переносом строк, без наложения. Предыдущее требование внешнего щита и ожидание другого официального мастера отменены этим выбором. Происхождение и история — `assets/SOURCE.md`; предыдущие reference и AI-кандидаты не подключать. Не делать из символа кнопку без назначенного адреса.

Внизу справа, в обычном потоке на всех ширинах: «Дюбкина Дарья Дмитриевна», под ним «Создатель и автор идеи». Никакого fixed-overlay; перенос имени допустим, выравнивание остаётся правым. ## 4. Адаптив и навигация

Переключение компоновки строго при 1100 px: ≥1100 — горизонтальная навигация и две колонки; <1100 — раскрываемое меню и одна колонка. В диапазоне 1100–1439 padding 32 px, на 1440 и выше 80 px; максимальная ширина ограничивает рост. 1440: шапка 112 px, nav от 64 px; пять ссылок в ряд. Для длинной четвёртой ссылки выделить минимум 300 px, разрешить две строки по словам, не обрезать, не сокращать и не уменьшать до нечитаемого размера. Активная ссылка: светлый текст, полоса 3 px под всей областью, aria-current=page. Золото может служить этой декоративной полосой. Область ссылки минимум 44 px высотой.

768: компактная шапка, меню «Разделы»; тело с одной основной колонкой, локальное оглавление над статьёй. 360: padding 20 px, нет горизонтального скролла. Заголовки и длинные ФИО переносятся по словам; overflow-wrap:anywhere только как страховка для URL и неразрывных данных. Не использовать ellipsis для имён/органов. Список структур не превращается в широкую таблицу.

Мобильное меню раскрывается под шапкой в потоке, не модальное и не полноэкранное. Кнопка «Разделы», aria-expanded, aria-controls; пять ссылок целиком вертикально. Текущий раздел виден и при закрытом меню. Escape закрывает и возвращает фокус кнопке, клик по ссылке закрывает после перехода. Нет focus trap. Без JS список изначально раскрыт; скрытие допустимо только после успешной инициализации. На desktop меню всегда видно. При 200–400% zoom включается тот же адаптив. Header/nav не фиксировать на малых экранах; локальное desktop-оглавление может быть sticky, если не выше viewport и не скрывает якоря.

## 5. Экран «Структура»

Порядок: H1 «Структура» → короткое объяснение различия территории и органа → спокойное предупреждение о частичном покрытии → поиск → двухколоночное исследование → источники.

На desktop левая колонка 288 px, gap 40 px, правая оставшаяся ширина. Слева H2 «Территория», список областей и Минска по подтверждённым данным; выбор региона открывает его список районов/городов. «Районы и города» появляются после региона, со ссылкой «Все территории» и хлебными крошками. Территория не изображается как юридическая подчинённость. Генеральная прокуратура — отдельная ссылка над территориальным списком. Не выводить шесть областей как детей Генпрокуратуры в географическом дереве.

Справа H2 выбранного органа, его проверенный уровень/подчинённость отдельным текстом, затем «Должностные лица», связанные органы, источники. Структура органов может быть отдельным семантическим вложенным списком с подписью «Подчинённость органов»; не смешивать его с географическим списком. Независимые/специализированные ветви выводить отдельной группой только при подтверждённых данных; не придумывать военную или транспортную ветвь. Не дублировать факты из разных осей без устойчивого ID.

ФИО полностью, должность отдельной строкой. У каждой записи источник, дата проверки и статус. Пустые должностные лица: «Нет проверенных данных о должностных лицах» + пояснение «Сведения будут добавлены после проверки источника». Частичная территория: «Сведения уточняются»; отсутствие строки не доказывает отсутствие органа. Для региона без дочерних записей — «Список районов и городов ещё не заполнен», а не «Районов нет».

Поиск с label «Найти орган или территорию», placeholder «Название органа, области, района или города», кнопка «Найти», очищение «Сбросить поиск». Нормализация регистра и пробелов, поиск не требует точного совпадения; не обещать морфологию. Результаты группировать «Органы» / «Территории», показывать путь и вид записи, количество в polite live region после отправки/паузы 300 ms, не на каждый символ. Нет результата: повторить запрос безопасным текстом, предложить сократить его и сбросить. Ошибка загрузки: «Не удалось загрузить справочник» и «Повторить»; при предвстроенных данных загрузку/скелетон не показывать. Во время реального fetch статус «Загружаем справочник…», aria-busy, сохранять размер панели. Никаких бесконечных спиннеров.

Mobile: поиск → выбор региона (обычный список ссылок или native select с кнопкой «Показать») → районы/города → материал органа. У перехода к органу есть постоянный якорь и ссылка назад к результатам; Back восстанавливает выбор/запрос из URL. Если JS выключен, весь справочник остаётся вложенными списками и sections с якорями, поиск скрыт как недоступное улучшение.

## 6. Экран «Обращение»

Порядок: H1 → учебное предупреждение «Этот сайт не принимает обращения» → оглавление → «Выберите ситуацию» (текстовые якорные ссылки по проверенным сценариям) → последовательность действий → что подготовить → куда перейти → источники/даты. Процедурные шаги используют ol, потому что последовательность значима; на desktop узкая левая колонка оглавления 240 px и статья до 72ch. Mobile оглавление раскрываемым details с видимой подписью.

Каждый шаг: действие, пояснение, проверенный официальный адрес/канал и источник. Сроки, формы, исключения и полномочия не назначать дизайнером. Если сведений нет — «Сведения уточняются», без фиктивной инструкции. Блок «Перед отправкой» — учебный перечень, а не интерактивная форма заявления. Главная CTA «Перейти к официальной информации» только с проверенным URL и подписью домена; не «Отправить обращение». Внешние ссылки по умолчанию в текущем окне, новая вкладка только с явным предупреждением. Длинные URL отображать осмысленным названием ссылки.

## 7. Экран «Поступление»

Порядок: H1 → краткое пояснение про службу → оглавление → подтверждённые требования → путь кандидата → документы/подготовка → полезные официальные контакты → источники. Не смешивать поступление в учебное заведение с поступлением на службу: если материал охватывает оба пути, дать два явно названных H2 с независимыми источниками. До проверки не обещать приём, вакансии, зарплату или соответствие требованиям.

Основное чтение как в «Обращении». Требования — компактный dl «Условие / пояснение», на mobile пары идут вертикально. Шаги только при подтверждённой последовательности. Сравнение двух путей допустимо таблицей с caption и заголовками; при 360 преобразовать в подписанные секции либо обеспечить локальный scroll с подсказкой, не всей страницей. CTA — официальный источник; формы заявки и загрузки документов нет. Пустые разделы честно обозначены, не заполняются общими юридическими фразами.

## 8. Экран «Направления деятельности прокуратуры»

Порядок: полный H1 без сокращения → вводный абзац → оглавление по проверенным направлениям → тематические H2 → определения/задачи → учебный пример при наличии → источник конкретного положения. На desktop H1 max-width 900 px и переносится естественно на две строки; на mobile занимает столько строк, сколько нужно, без сжатия шрифта.

Не делать сетку одинаковых карточек. Основной паттерн — оглавление и разделы статьи с тонкими горизонтальными разделителями. У каждого направления собственный постоянный якорь; рядом «Скопировать ссылку» как JS-улучшение со статусом «Ссылка скопирована», при отказе буфера — «Скопируйте адрес из строки браузера». Заголовок сам остаётся обычным якорем без JS. Юридические термины имеют краткие пояснения в тексте или details «Пояснение», без tooltip как единственного носителя информации. Примеры помечать «Учебный пример», не выдавать за реальное дело.

## 9. Экран «Интерактивы»

Порядок: H1 → пояснение локального учебного режима → три внутренних якоря «Тесты», «Ребусы», «Загадки» → список упражнений с названием/типом и доступной длительностью только при расчёте → активное упражнение → обратная связь → связанные материалы. Это не дополнительные верхние вкладки. Без рейтинга, таймера, авторизации и отправки результата. Состояние по умолчанию в памяти страницы; сохранение прогресса не обещать. Если введено localStorage, нужна видимая команда «Сбросить прогресс» и сообщение об отказе хранилища, без блокировки решения.

Тест: один вопрос или небольшая целостная группа; fieldset/legend, radio с полными labels, достаточно воздуха. «Проверить ответ» активна после выбора; текстовая подсказка до выбора объясняет это. Enter/Space работают штатно. После проверки выбор остаётся видимым, показываются «Верно» либо «Ответ пока неверный», пояснение почему и ссылка на учебный раздел/источник. Никогда только зелёная/красная рамка. «Следующий вопрос» появляется после проверки; «Попробовать ещё раз» сбрасывает выбор и обратную связь текущего задания. Число вопросов Y фиксировано для выбранного теста. Засчитывается только первая проверенная попытка каждого вопроса; повторная проверка и «Попробовать ещё раз» не меняют балл. Открытие решения до первого верного ответа даёт 0 за вопрос. «Пройти заново» создаёт новую попытку и обнуляет её счёт. Результат: «Верных ответов: X из Y», список тем для повторения, «Пройти заново»; не присваивать официальную оценку знаний.

Ребус: настоящее предоставленное изображение с подписью и текстовой альтернативой, поле «Ваш ответ», «Проверить», details/кнопка «Подсказка», затем «Показать решение». Загадка использует текст вместо изображения. Нормализовать регистр, пробелы и заранее заданные допустимые варианты; не угадывать семантическую правильность произвольного ответа. Пустой ответ: ошибка у поля «Введите ответ», aria-describedby/aria-invalid, фокус на поле. Неверный: сохранять введённое, предложить подсказку; верный: объяснить ход решения. После раскрытия решения явно «Решение открыто», не засчитывать самостоятельный ответ. Изображение отсутствует/ошибка: текстовая версия, если она полноценна; иначе «Ребус временно недоступен», без фиктивной картинки.

Переходы вопроса без анимации, заголовок нового вопроса получает программный фокус tabindex=-1 после действия, не после каждого ввода. Результат объявляется polite live region. Для статических упражнений нет loading. Только при реальном асинхронном чтении данных: локальный статус загрузки и ошибка с повтором; не терять уже введённый ответ. Пустой каталог: «Упражнения ещё не добавлены» + ссылка на чтение. Без JS: вопросы и варианты читаются, решения доступны в details; кнопки проверки скрыты, сверху «Автоматическая проверка требует JavaScript. Решения доступны ниже». Не оставлять неработающие кнопки.

## 10. Общие компоненты и состояния

Ссылка: подчёркнута в тексте, underline-offset 3 px; hover темнее/толще подчёркивание, visited допускается отдельным проверенным контрастным оттенком. Кнопка: navy/white, padding 12×20, min-height 44; hover navy-deep, active без смещения контента; disabled видимая причина рядом, не только пониженная opacity. Поля: белые, 1 px control-border, min-height 48, label всегда снаружи. Ошибка — текст после поля и связь aria-describedby. Валидировать по отправке, затем корректировать по вводу, не ругать до взаимодействия.

Фокус :focus-visible — 3 px focus-light с offset 3 px на светлом и focus-dark на тёмном. Не убирать outline; не клиповать его overflow. Фокус не должен перекрываться sticky-блоком. Hover никогда не единственный способ раскрыть информацию. Details используют нативный summary с доступной областью 44 px; видимый индикатор раскрытия — простой SVG chevron, не emoji. Статусы имеют текст, а не одиночный значок.

Метаданные: «Источник: [название]», «Проверено: [дата]», «Статус: подтверждено / требует проверки». Дата обновления файла не подменяет дату проверки факта. Проверенный и непроверенный материал различать текстом. Непроверенные ссылки не становятся официальными утверждениями. При недоступном источнике показывать статус и дату последней проверки, не скрывать проблему. Общая библиография дополняет, но не заменяет привязку к конкретным положениям.

## 11. Доступность, устойчивость и движение

HTML lang=ru, UTF-8, landmarks, логичная H1–H3 и DOM-последовательность совпадают с визуальной. Keyboard: все функции доступны Tab/Shift+Tab/Enter/Space, radio управляются стрелками. Не назначать положительный tabindex. Touch target ≥44×44 px; соседние маленькие ссылки разнести. Ошибки/результаты не озвучивать несколькими live region одновременно. Выбранный регион, активный раздел и раскрытость имеют семантические состояния. У данных с настоящими столбцами — table, у навигации — списки ссылок.

Не использовать анимацию появления контента. Разрешён переход цвета/подчёркивания 120 ms ease-out, без параллакса/автопрокрутки. prefers-reduced-motion отключает все необязательные transitions и smooth scroll. По якорям scroll-margin-top 24 px, при sticky 96 px. Selection #DCEAF7 с ink, caret ink. Стандартная полоса прокрутки остаётся доступной, без узкого кастомного скроллбара. prefers-contrast/forced-colors сохраняют границы, underline и outline системными цветами.

Изображения имеют width/height и разумный размер; нет сетевых шрифтов и тяжёлых библиотек ради меню/квизов. Факты доступны в HTML либо есть полноценный статический fallback; JS только улучшает. Не хранить обращения, контакты пользователя или ответы на сервере. Все примеры в QA маркируются тестовыми и не попадают в справочник как реальные сведения.
